## 两个有用的机制

`Orbit.envelope_closed` 需要显式 `CompositionClosed`，`envelope_covers` 需要显式 `HasIdentity`。因此不能从“所有允许像之并”这几个字自动获得复合稳定性；要在实际 IUT 允许族上提供相应证明。本轮的稳定容器模型为后续处理 Ind1 提供接口，但没有实现该接口。

`LocalNumerics` 的权重统一用 1/105 为单位。Lean 检查的是清除分母后的整数等式及条件命题：

| 项目 | 模型中的数值 |
|---|---:|
| 候选原阈值 | `floor((810−414−6)/105)×105+6 = 321` |
| 层保持假设下，四因子测量和上界 | `≤ 210`，故不能满足 `≥ 321` |
| 用来源权重 135 替换 810 后的阈值 | `floor((135−414−6)/105)×105+6 = −309` |
| 同一模型对放宽后阈值的结论 | 测量和 `≥ −309` |
| 线性表达式的变化 | `675/105 = 45/7`（Lean 检查交叉相乘等式） |
| 取整后 cut 的变化 | `630/105 = 6`（Lean 检查整数等式） |

这两种代价不同。不能把局部容器扩大后的包含成立，写成原体积估计已经恢复，更不能据此推出 abc。`swap23_rho_positions` 还检查：theta 从 source slot 3 移到 target slot 2 时，place 仍为 b1，rho 分子仍为 1；目标最后一个 slot 3 的 place 为 b2，rho 分子为 6。

## 验证工程修复

第一轮验证器确有可复现漏洞：B 通过一个值为 `PLift True` 的 `def` 间接引用 A 时，旧图漏掉 A→B，可能使 A 未获 VS Code 准入而 B 获准入。该缺陷属于依赖图与门禁，未显示 Lean 内核错误。

第二轮导出全部项目模块常量，沿辅助常量追踪到最近的目录定理，并按依赖闭包传播待验收状态。真实 Lean 最小例已复现并验证修复，证据见 `verification/round2-helper-regression.json`。另外有 33 项 Python 回归测试，含快照漂移、stderr、目录失配及观察凭据缺失/错误绑定；见 `verification/round2-regression-tests.json`。Python 测试是工程证据，不列为数学 fact-tree 节点。

验证还加入明确目录、声明来源模块核对、编辑器入口逐目标检查、全部证明源码和验证工具快照，以及导入编译产物与实际 Lean/Lake 二进制的前后哈希。当前运行记录 15 个源/配置输入与 7075 个运行产物。快照目的为复现和发现意外漂移，不构成防恶意篡改证明；操作系统、扩展及未列出的运行库仍为信任边界。
