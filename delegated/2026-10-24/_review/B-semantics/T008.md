## 2. 最硬的一条：`letI` 论述的反向错误

### 断言原文

- `ARROW-TABLE.md:87`：「若忘记 `letI := muAction …`，`ContH1.map` 的 `hcomp` 与 `reduceMu_smul` 里的右侧 `σ •` 会落到**另一个**作用上，语句变成不同命题（**通常无法关闭**，偶有歧义实例时更危险）。」
- `SUMMARY.md:29`：「`muAction` 必须经 `letI` 消费；忘记 `letI` 会静默落到 `Mu n κ` 上 `Gal(κ/k)` 的**另一个**作用实例。」

### 独立探针实测

`_review/B-semantics/probe/BLetIProbe.lean`（去掉 `letI`）→ `lake env lean -DwarningAsError=true`：

```
BLetIProbe.lean:31:0: error: failed to synthesize
  MulDistribMulAction (↥(ValuationSubring.decompositionSubgroup F A)) (Mu n (ResidueField ↥A))
BLetIProbe.lean:35:66: error(lean.synthInstanceFailed): failed to synthesize instance of type class
  HSMul (↥(ValuationSubring.decompositionSubgroup F A)) (Mu n (ResidueField ↥A)) ?m.66
```

`_review/B-semantics/probe/BLetIControl.lean`（带 `letI`，即生产源码写法）→ **exit 0，零输出、零 error、零 warning**。
两文件仅差 `letI` 一行，故两个错误可精确定位到该行。

### 实例穷举（全工程 `.lean` 检索）

`Mu` 上的 `MulDistribMulAction` 实例只有两处：

- `ContinuousKummerTheory/Kummer/Basic.lean:86` — `instance : MulDistribMulAction Gal(Ω/K) (Mu n Ω)`，**作用群是 `Gal(Ω/K)`**；
- `ContinuousKummerTheory/Kummer/Decomposition.lean:140` — `muAction`，作用群是 `↥(decompositionSubgroup F A)`，但它是 `def` 不是 `instance`。

### 结论

1. **不存在**「`Gal(κ/k)` 作用在 `Mu n κ` 上」的实例；唯一的全局实例作用群是 `Gal(Ω/K)`（不是 `Gal(κ/k)`），且作用对象是 `Mu n Ω`。
2. `Gal(Ω/K)` 与 `↥(decompositionSubgroup F A)` **不同一**，故 `Basic.lean:86` 的实例根本不能充当替代品。
3. 省略 `letI` 的后果是**硬合成失败（hard error），不是静默换作用**。文中「语句变成不同命题」「通常无法关闭」均为**不可复现**的描述——错误发生在** elaboration 阶段**，语句根本建立不起来，不存在「变成另一个命题」。
4. 正确的记法应为：`muAction` 因是 `def` 而**默认不在实例搜索里**，所以点位（`σ • ζ` 出现在 `reduceMu_smul` 的陈述与 `decomposition_kummer` 的 `letI` 体）**必须显式 `letI`，否则不通过 elaborator**。「必须写」成立，「会静默降级」不成立。

**影响**：不破坏 A07/A10/A14 的「已构造」判定（它们都在源码里显式 `letI`），但这是台账里唯一一处**把机制说反**的语义条目，且 SUMMARY 把它列为「准确前提」之一，会被下游当作隐患去排查一个不存在的坑。

**建议（不代改）**：`ARROW-TABLE.md:85-88` 与 `SUMMARY.md:29` 把「静默落到另一个实例」改为「默认不参与实例合成 → 不写 `letI` 直接合成失败（探针证据）」，并删去「偶有歧义实例时更危险」。
